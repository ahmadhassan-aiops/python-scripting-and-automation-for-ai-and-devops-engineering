# 37. Project - Log Archiving Automation

Log files grow until they fill the disk. This script **archives** a log when it gets too big, then empties it so the service can keep writing.

**Plan:**

1. Check the log file's size with `os.stat()`
2. If it's 1 MB or more, compress it into a dated `.tgz` archive
3. Empty the original file
4. Run the script every day with cron

## The Script

```python
# archive_log.py
#!/usr/bin/python3
"""Archive a log file into a dated .tgz when it reaches a size limit."""
import os
import tarfile
from datetime import date

LOG_FILE = "/var/log/syslog"          # on RHEL/CentOS: /var/log/messages
LIMIT_MB = 1.0

today = date.today().strftime("%d%B%Y")
file_mb = os.stat(LOG_FILE).st_size / 1_000_000
print(today)
print(f"{file_mb} MB")

if file_mb >= LIMIT_MB:
    print("File is huge, proceeding to archive")
    archive_path = f"{LOG_FILE}_{today}.tgz"
    with tarfile.open(archive_path, "w:gz") as tar:
        tar.add(LOG_FILE)
    open(LOG_FILE, "w").close()       # empty the log, keep the file and its permissions
    print(f"Archive created: {archive_path}")
else:
    print("File is small")
```

- `os.stat(path).st_size` is the size in bytes; dividing by 1,000,000 gives MB.
- Python's built-in **tarfile** module creates the `.tgz` directly, so there's no need to call `tar` and `gzip` through `os.system()`.
- Opening the file in `"w"` mode and closing it empties it without deleting it, so the logging service keeps its file handle and permissions.

## Test Run

Let the script handle a fake log first, never a real one on the first try:

```console
root@ahmadhassan:~/archive_logs# ls -lh app.log
-rw-r--r-- 1 root root 1.9M Oct 19 18:45 app.log
```

```console
root@ahmadhassan:~/archive_logs# python3 archive_log.py
19October2026
1.94889 MB
File is huge, proceeding to archive
Archive created: app.log_19October2026.tgz
```

```console
root@ahmadhassan:~/archive_logs# ls -lh
total 112K
-rw-r--r-- 1 root root    0 Oct 19 18:45 app.log
-rw-r--r-- 1 root root 108K Oct 19 18:45 app.log_19October2026.tgz
-rw-r--r-- 1 root root  670 Oct 19 18:45 archive_log.py
```

```console
root@ahmadhassan:~/archive_logs# python3 archive_log.py
19October2026
0.0 MB
File is small
```

The first run archived the 1.9 MB log and emptied it; the second run found it small and did nothing. A real system log is usually archived by **logrotate**, but this pattern works for any application log that has no rotation set up.

## Schedule It

```text
10 0 * * * /usr/bin/python3 /root/myproject/archive_logs/archive_log.py >> /var/log/archive_log.out 2>&1
```

This runs every night at 00:10. On Windows, run it from Task Scheduler with a batch file (topic 28).
