# 10. Modules and pip

A **module** is a Python file whose code you can reuse in other programs. Instead of copying code between scripts, you put it in one file and **import** it.

There are three kinds of modules:

1. **Your own modules:** any `.py` file you write
2. **Built-in modules:** shipped with Python, such as `os`, `sys`, `datetime` and `json`
3. **Third-party modules:** installed with `pip`, such as `pandas`, `requests` and `paramiko`

## 1. Creating Your Own Module

```python
# mylname.py
lname = "Hassan"
```

Three ways to import it:

```python
# myscript.py
import mylname
print(mylname.lname)
```

```console
root@ahmadhassan:~/lect15# python3 myscript.py
Hassan
```

```python
# myscript2.py
import mylname as ah          # an alias
print(ah.lname)
```

```console
root@ahmadhassan:~/lect15# python3 myscript2.py
Hassan
```

```python
# myscript3.py
from mylname import *         # import every name directly
print(lname)
```

```console
root@ahmadhassan:~/lect15# python3 myscript3.py
Hassan
```

> **Warning:** never name your own script after a built-in module, for example `os.py` or `json.py`. Python would import your file instead of the real module.

`from module import *` is handy in the shell, but in scripts prefer `from module import name` so it's clear where each name comes from.

## 2. Built-in Modules

```python
# builtin.py
import os
os.system("hostname")
print(os.getcwd())
```

```console
root@ahmadhassan:~/lect15# python3 builtin.py
ahmadhassan
/root/lect15
```

`dir(os)` lists everything a module offers, and `help(os.getcwd)` explains one function.

## 3. Third-Party Modules with pip

Packages come from the Python Package Index: https://pypi.org/

```console
root@ahmadhassan:~# pip --version
pip 22.2.1 from /usr/local/lib/python3.10/site-packages/pip (python 3.10)
root@ahmadhassan:~# python3 --version
Python 3.10.6
```

Importing a package that isn't installed fails:

```python
>>> import pandas
>>> import selenium
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ModuleNotFoundError: No module named 'selenium'
```

| Task | Command |
|---|---|
| Install the latest version | `pip install pandas` |
| Install a specific version | `pip install pandas==1.3.4` |
| Upgrade a package | `pip install --upgrade pandas` |
| Remove a package | `pip uninstall pandas` |
| See installed packages | `pip list` |
| Save requirements | `pip freeze > requirements.txt` |
| Install from requirements | `pip install -r requirements.txt` |
| Upgrade pip itself | `pip install --upgrade pip` |

Check the version from Python:

```python
>>> import pandas
>>> pandas.__version__
'1.3.4'
```

### A real DevOps scenario

1. Your manager asks for **pandas 1.3.4**, so you install it with `pip install pandas==1.3.4`.
2. Later the security team reports a **vulnerability** in that version and asks you to move to 1.4.3.
3. You upgrade with `pip install --upgrade pandas` (or `pip install pandas==1.4.3` to pin it), then confirm with `pandas.__version__`.

> On modern Linux distributions, install packages inside a **virtual environment** (`python3 -m venv venv` then `source venv/bin/activate`) so they don't conflict with system packages.
